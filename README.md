# 🚀 RetailCRM Sales Intelligence Dashboard & Telegram Bot 

Добро пожаловать в проект интеграции **RetailCRM → Supabase** с красивым аналитическим дашбордом в стиле **Glassmorphism** и Telegram-ботом для моментальных уведомлений о VIP-заказах (>50,000 ₸).

## 🛠 Архитектура проекта
1. **`upload_mock.py`** — Генератор и загрузчик тестовых заказов в RetailCRM (v5 API).
2. **`pusher_supabase.py`** — ETL-скрипт. Синхронизирует данные заказов и товаров напрямую из RetailCRM в вашу базу данных на Supabase.
3. **`dashboard/`** — Клиентская статистика (Vanilla JS + Chart.js + HTML/CSS). Строит 6 графиков в реальном времени.
4. **`telegram_bot.py`** — Поллинг-воркер, который уведомляет в Telegram о новых жирных заказах.

## 🤖 Как мы это строили (Отчет Claude Code)

### Основные промпты, которые задавали направление:
- Напиши скрипт синхронизации данных из RetailCRM в Supabase. Обработай данные: вытащи имя, телефоны, сумму, адреса доставки и залей с `on_conflict=id`.
- Измени стилистику дашборда на современный, сначала "Minimalism & Swiss Style", а затем **"Glassmorphism"** с блюром, тенями и анимацией. Поменяй рубли на тенге.
- Добавь, чтобы в Supabase пушились только новые данные без создания дубликатов (`ignore_duplicates`).
- В дашборде всё сливается в один день. Добавь случайные `createdAt` даты в историю за последние 30 дней.
- Расширь аналитику: добавь Выручка по продуктам, Каналы привлечения, Заказы по городам, Выручка по каналу, Средний чек по каналу.
- Убери KPI карточку "Success Rate".
- Напиши Telegram бота с polling (каждые 60 сек), `last_check.json` и суммой > 50000 ₸.

## 🚧 Где мы застряли и Как красиво решили

### 1. Проблема: Ошибка базы данных `PGRST204` при первом дампе
**Где застрял:** Supabase категорически отказывался принимать JSON от `pusher_supabase.py`, выбрасывая ошибки `HTTP 400 Bad Request`.
**Как решил:** Понял, что Python-скрипт пытался загрузить ключи (например, `article` и `delivery_type`), которых банально не существовало в схеме таблицы Supabase. Я сгенерировал SQL-миграцию `schema.sql` для создания всех недостающих таблиц и связей с правильными типами данных.

### 2. Проблема: Все графики сливаются в "Сегодня"
**Где застрял:** График Revenue показывал гигантскую синюю точку из 100 заказов за один день, потому что у мок-данных не было поля `createdAt`.
**Как решил:** Написал на лету Python-сниппет, который рандомно разбросал поле `createdAt` по всем 150 заказам на промежуток последних 30 дней и обновил файл.

### 3. Проблема: Метрика Источников светится как "Unknown"
**Где застрял:** Я добавил вытягивание `customFields.utm_source` из-за запроса пользователя, но дашборд упорно показывал заглушки (Unknown), хотя в JSON эти поля были!
**Как решил:** Догадался, как работает RetailCRM — API жестко удаляет любые нестандартные ключи (customFields), если они вручную не зарегистрированы в системных настройках администратора. Предложил пользователю легитимный путь: добавить кастомное поле `utm_source` внутри UI RetailCRM.

### 4. Проблема: Бесконечные спиннеры-загрузки на графиках
**Где застрял:** После добавления 5 новых графиков HTML-разметка кардинально изменилась, но JS упорно отказывался всё рисовать — циферки висели "0" и крутились лоадеры.
**Как решил:** Раскусил классическую ловушку `python3 -m http.server`. Браузер отдал свеженький HTML, но подсунул кэшированную старую версию `app.js`, которая не нашла нужных `ID` и крашнулась. Мгновенно вылечил добавив `?v=2` в пути файлов (cache-busting).

### 5. Проблема: Telegram Bot не видел новых заказов
**Где застрял:** Бот стартовал с `Найдено заказов: 0`, хотя в логах `upload_mock.py` летело по 50 заказов. 
**Как решил:** Оказалось, что `upload_mock.py` загружало заказы с **мартовскими** датами (из пункта №2), а бот по моему же коду делал запрос `filter[createdAtFrom]` = `Сейчас - 1 час`. Я временно откатил `last_check.json` ко времени первого мартовского заказа, и бот сразу же проглотил весь батч!

## 🚀 Деплой
1. Настройте файл `.env`.
2. Поднимите таблицы в Supabase.
3. Запустите дашборд `python3 -m http.server 8042`.
4. Запустите поллинг `python telegram_bot.py`.
